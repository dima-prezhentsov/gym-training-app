# Повторная загрузка не показывала результат

## Что это оказалось

Defect: кнопки повторяли запрос данных поверх неуспешной backend-сессии, а быстрая повторная ошибка визуально возвращала тот же экран без уведомления.

## Как выглядела проблема

После нажатия «Повторить» пользователь не видел устойчивого индикатора загрузки или нового сообщения об ошибке и воспринимал кнопку как неработающую.

## Куда смотрели

| Гипотеза | Чем проверяли | Итог |
|---|---|---|
| View model не включает loading | `HomeViewModel`, `ScheduleViewModel`, `WorkoutViewModel` | Убита: состояние включается до запроса |
| Экран не отображает loading | error-ветки home, schedule, history, workout | Убита: индикаторы предусмотрены, но короткое состояние может не попасть в кадр |
| Повтор не восстанавливает backend-сессию | обработчики «Повторить» и `BackendSession` | Подтверждена: обработчики вызывали только repository load |
| Ошибка после повтора нигде не показывается | поиск `SnackBar` по экранам | Подтверждена для загрузки страниц |

## Что нашли

`BackendSession.initialize` кэширует завершившуюся попытку, а прежние обработчики страниц вызывали только методы загрузки view model. Репозитории немедленно отклоняли запрос при неаутентифицированной сессии; UI возвращался к тому же inline error-state.

## Что изменили

| Файл | Что |
|---|---|
| `backend_session.dart` | Добавлена условная `ensureAuthenticated`: активная сессия не трогается, failed/disabled восстанавливается |
| `async_action_button.dart` | Общая кнопка с индикатором и защитой от повторного тапа |
| `app_error_feedback.dart` | Условная проверка backend и единый безопасный `SnackBar` |
| Экраны home/schedule/history/workout/profile | Повторные действия подключены к общему механизму |

Было: кнопка сразу вызывала `viewModel.load()`.

Стало: обработчик при необходимости восстанавливает сессию, выполняет загрузку и показывает ошибку через `SnackBar`; сама кнопка отражает выполнение.

Почему: устраняет немедленный повтор поверх failed-сессии и даёт видимую обратную связь.

## Как убедились

- Регрессионные тесты сначала не компилировались без `ensureAuthenticated` и `AsyncActionButton`.
- После изменения точечные unit/widget-тесты прошли.
- Widget-тест failing repository подтверждает индикатор после тапа и сообщение внутри `SnackBar` после повторной ошибки.

## Тексты

Ошибка повторной загрузки исправлена. В следующей web-сборке кнопка покажет процесс подключения, а при повторной ошибке — понятное уведомление. Повторная Telegram-авторизация выполняется только когда текущая сессия не активна.

## Что осталось

Нужна ручная проверка на телефоне после публикации GitHub Pages; backend API и схема Neon этим изменением не затрагиваются.
