# Часть 4 из 4: история и deploy

## Контекст

Auth и расписание используют backend. Эта часть завершает persistence-срез и готовит production-конфигурацию.

## Что делает эта часть

1. Добавляет schema/migration записей тренировок, упражнений и подходов.
2. Добавляет endpoint чтения и сохранения истории владельца.
3. Добавляет Flutter API repository и mapping.
4. Документирует backend deploy, CORS, secrets и compile-time API URL.
5. Выполняет полную проверку и закрывает progress/report.

## Чего не делает

Не реализует аналитику динамики роста и восстановление незавершённой тренировки.

## Готово, когда

Завершённая тренировка появляется в истории после нового запуска приложения, production web build принимает backend URL, полный набор тестов проходит.
