# Активная тренировка — спецификация

## Цель

Пользователь проходит запланированный тренировочный день, фиксирует повторения и рабочий вес, завершает тренировку и сразу видит неизменяемую запись в истории.

## Границы

- Входит: одна активная тренировка, добавление и удаление подходов, таймер, завершение, локальная история и просмотр деталей.
- Не входит: backend, синхронизация между устройствами, восстановление после перезапуска страницы, редактирование завершённой записи и аналитика прогресса.

## Принятые решения

- Одновременно существует не более одной активной тренировки.
- Выход с экрана сохраняет активную тренировку в памяти; повторный вход продолжает её.
- Завершение доступно после добавления хотя бы одного подхода.
- Вес допускает ноль для упражнений с собственным весом; повторения должны быть больше нуля.
- Запись хранит снимок названия тренировки, упражнений и групп мышц, поэтому изменения расписания не переписывают историю.

## Связанность

| Что | Обновить | Почему |
|---|---|---|
| Главный экран | Да | Существующая кнопка «Начать тренировку» должна открывать реальный сценарий |
| Расписание | Да | Каждый тренировочный день должен запускаться напрямую |
| История | Да | Должна показывать завершённые записи и детали |
| Нижняя навигация | Нет | Активная тренировка открывается поверх shell без нижнего меню |
| Telegram bridge | Нет | Новых возможностей Telegram API не требуется |
| Backend и аккаунт | Отложено | Текущий этап явно использует in-memory repository |
| Недельная статистика | Отложено | Демо-агрегаты будут заменены после backend-интеграции |

## Шаги

1. Добавить `SetRecord`, `ExerciseRecord`, `ActiveWorkout` и `WorkoutRecord`.
2. Добавить `WorkoutRepository` и in-memory реализацию.
3. Добавить app-scoped `WorkoutViewModel` с запуском, подходами и завершением.
4. Добавить полноэкранный маршрут `/workout/:dayId` вне navigation shell.
5. Подключить запуск с главного экрана и из расписания.
6. Реализовать экран активной тренировки и валидированную форму подхода.
7. Заменить пустой экран истории списком и деталями записей.
8. Покрыть правила unit-тестами и пользовательский поток widget-тестом.
9. Проверить мобильный web UI и production build.

## Разбивка

Влезает в одну сессию, но фиксируется двумя ключевыми коммитами: доменная логика, затем пользовательский интерфейс и интеграция.

## Успех

Пользователь запускает день, добавляет подход, завершает тренировку и видит её в истории без перезапуска приложения.
