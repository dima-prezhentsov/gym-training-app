# Отключение вертикальных свайпов Telegram

## Зачем

Жест прокрутки Flutter-контента конфликтовал с нативным жестом Telegram и мог свернуть Mini App до того, как пользователь возвращался к началу списка.

## Что было и что стало

Раньше Telegram всегда мог перехватить вертикальный свайп внутри контента. Теперь клиенты с Bot API 7.7+ не сворачивают приложение свайпом по контенту; сворачивание через заголовок Telegram остаётся доступным.

## Что нашли по дороге

Официальный API поддерживает полное включение или отключение вертикальных свайпов, но не атомарный режим, зависящий от позиции Flutter-скролла. Выбран стабильный режим полного отключения внутри контента.

## Спецификация

1. Расширить существующий JS interop методами `isVersionAtLeast` и `disableVerticalSwipes`.
2. После `ready()` и `expand()` отключать свайпы только при поддержке Bot API 7.7.

## Как это легло в код

| Файл | Что |
|---|---|
| `lib/telegram/telegram_web_app_web.dart` | Добавлены официальные методы Telegram WebApp и защищённый по версии вызов при инициализации |

## Пропуски в задаче

Поведение старых клиентов не было оговорено. Сохранено прежнее поведение, потому что API управления свайпами появился только в Bot API 7.7.

## Конвенции

Изменение продолжает существующий `dart:js_interop` bridge и остаётся внутри web-реализации conditional import. Новых слоёв и зависимостей нет.

## Как проверяли

Логика сопоставлена с официальным Telegram Mini Apps API. Выполнены форматирование, статический анализ, Flutter-тесты и production web build.

## Требуется до мержа

Ничего: регенерация, миграции и конфигурационные изменения не требуются.

## Узкие места рядом

Автоматические VM-тесты не могут эмулировать нативный Telegram WebView и его жесты; отдельную тестовую инфраструктуру для одного interop-вызова не добавляли.

## Что осталось

Ручная проверка жестов на физическом Android или iOS устройстве после деплоя.
