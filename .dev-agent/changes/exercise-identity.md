# Идентичность упражнения при переименовании

## Зачем

История и графики должны относиться к конкретному упражнению. Название пользователь может исправить, поэтому оно не служит идентификатором.

## Что было и что стало

Раньше упражнение в расписании можно было только удалить и создать заново. Теперь у него можно изменить название, сохранив прежний `exerciseId` и группу мышц. Новое упражнение всегда получает новый ID, в том числе при совпадении названия с удалённым.

## Как это работает

- `ExerciseFormDialog` в режиме редактирования показывает только поле названия и возвращает копию упражнения с исходным ID, описанием и группой мышц.
- `TrainingDayForm` заменяет упражнение с этим ID в текущем списке и сохраняет расписание через существующий репозиторий.
- `calculateProgressOverview` группирует записи по ID. Для действующего упражнения показывает название из расписания; для удалённого — последнее название в выбранной истории.
- Историческая запись тренировки сохраняет снимок имени и группы мышц на момент завершения. Подходы по группам мышц рассчитываются из этих снимков.
- Серверный контракт уже содержит публичный ID в расписании и истории; миграция не нужна.

## Проверка

- Widget-тест: переименование через интерфейс сохраняет ID и группу мышц; поля изменения группы и описания недоступны.
- Unit-тест: записи до и после переименования образуют один ряд прогресса.
- Unit-тест: одинаковое имя с новым ID образует отдельный ряд.
- Ручная проверка в Telegram выполняется пользователем.
